## Status and evidence semantics

| Status | Meaning in this matrix |
|---|---|
| `VERIFIED_LOCAL` | The requirement has an implemented local boundary and direct local test or read-back evidence. For fixture rows, this means system/control integrity only. It does not imply scientific or external validity. Final frozen suite evidence can still be `PENDING`. |
| `IMPLEMENTED_UNTESTED_EXTERNAL` | A typed interface or adapter is implemented and locally contract-tested, but its behavior against a real external service, authority, data source, scheduler, or hardware has not been exercised. |
| `BLOCKED_LOCAL` | A required local control or working path is unfinished. A verified refusal boundary does not complete the underlying requirement; resolve local engineering before goal completion unless an actual unavailable prerequisite is demonstrated. |
| `BLOCKED_EXTERNAL` | Satisfying the requirement needs unavailable credentials, network access, licensed data, independent authority, or hardware. A mock or fixture does not clear the blocker. |
| `PENDING_FINAL_VERIFICATION` | The non-blocked implementation exists, but the final frozen captured suite/run/report/audit authority has not yet been produced. This is not an implementation gap and cannot be upgraded from development evidence. |
| `PARTIAL` | Direct evidence proves only part of the named requirement. Missing historical evidence or unresolved substantive controls remain explicit; this is not completion. |
| `HISTORICALLY_UNVERIFIABLE` | The preserved historical report cannot be independently reproduced or fully revalidated from the recovered evidence. This does not establish that the historical report was false. |
| `NOT_IMPLEMENTED` | A material local implementation path is absent. No current row uses this label merely for a pending final count or digest. |
